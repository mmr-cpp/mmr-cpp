# HL7
 
## Healthcare Interoperability Standards
- Interoperability allows different healthcare systems, devices, and applications to securely access, exchange, and use health information.
- It ensures seamless communication between hospitals, clinics, laboratories, pharmacies, and imaging systems.
- Common interoperability standards:
- HL7 v2
- HL7 v3
- HL7 FHIR (Fast Healthcare Interoperability Resources)
- DICOM (for medical imaging)

## Levels of Interoperability
### 1. Foundational Interoperability
- Basic ability of one healthcare system to exchange data with another.
- Systems can send and receive data successfully.
- The receiving system may not understand or interpret the data internally.
### 2. Structural Interoperability
- Defines the format, structure, and organization of exchanged data.
- Ensures data fields are mapped correctly.
- Examples:
- HL7 message structure
- XML and JSON data formats
### 3. Semantic Interoperability
- Enables systems to exchange data with the same meaning and interpretation.
- Uses standard terminologies and coding systems.
- Examples:
- SNOMED CT
- LOINC
- ICD-10
- RxNorm
### 4. Organizational Interoperability
- Supports secure, legal, and policy-compliant data sharing between organizations.
- Includes governance, privacy, security, and regulatory requirements.
- Example:
- HIPAA compliance
- Patient consent management

## HL7 Version 2 (HL7 v2)
- Introduced in 1989 and is the most widely used healthcare messaging standard.
- Enables communication between healthcare applications such as:
- HIS (Hospital Information System)
- EMR/EHR
- RIS (Radiology Information System)
- LIS (Laboratory Information System)
- PACS (Picture Archiving and Communication System)
 
### Features
- Text-based messaging standard.
- Uses pipe (`|`) and caret (`^`) delimiters.
- Event-driven communication.
- Supports real-time data exchange.
 
### Common Message Types
- ADT (Admission, Discharge, Transfer)
- Patient registration and demographic updates.
- ORM (Order Message)
- Sends clinical orders such as radiology or lab requests.
- ORU (Observation Result)
- Sends diagnostic results and reports.
- SIU (Scheduling Information Unsolicited)
- Appointment and scheduling information.

### Limitations
- Different implementations may vary between vendors.
- Difficult to standardize completely.
- Limited support for modern web technologies.
 
### HL7 FHIR
- Modern HL7 interoperability standard.
- Enables healthcare data exchange through RESTful APIs.
 
### FHIR Resources
- Modular healthcare entities:
- Patient
- Observation
- Encounter
- Practitioner
- Medication
 
### FHIR Search
- Standardized search parameters.
- Supports efficient retrieval of healthcare records.
 
### Terminologies
- Standard coding systems used with CDA and FHIR:
- SNOMED CT
- LOINC
- ICD
- RxNorm
